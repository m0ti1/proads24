# Персональные данные: памятка владельцу proads24

Папка содержит публичные документы для формы заявки на сайте:

- `index.html` — политика обработки персональных данных;
- `consent.html` — отдельное согласие посетителя на обработку данных;
- `request.html` — порядок направления запроса, отзыва согласия и требования об удалении данных.

Документы составлены под фактический состав полей формы: имя, телефон, компания,
email, тема обращения, рекламный бюджет и комментарий. Специальные категории и
биометрические данные через сайт не запрашиваются.

## Обязательно перед коммерческим запуском

1. Заменить во всех документах обозначение «владелец и администратор сайта proads24»
   на полное наименование юридического лица либо ФИО ИП/физического лица. Указать
   фактический адрес регистрации, ИНН и ОГРН/ОГРНИП. Сейчас эти сведения отсутствуют
   в исходных материалах, поэтому они намеренно не выдуманы.
2. Заменить демонстрационные телефон, email и адрес на реальные. Это прямо отмечено
   в `PRODUCT.md` проекта.
3. До начала реального сбора заявок направить уведомление в Роскомнадзор, если к
   обработке не применимо законное исключение, и сверить цели, состав данных, сроки,
   способы обработки и места нахождения баз с опубликованной политикой.
4. Подключить российский backend/CRM и первичную базу данных на территории РФ.
   GitHub Pages подходит для демонстрационной статики, но не заменяет инфраструктуру,
   отвечающую требованиям локализации баз персональных данных граждан РФ.
5. Сохранять доказательство согласия: версию текста, дату и время, адрес страницы,
   состав формы и технические сведения, позволяющие подтвердить действие посетителя.
   Версия согласия уже передаётся скрытым полем `consent_version`.
6. Заключить необходимые договоры/поручения с CRM, почтовым, хостинговым и иными
   подрядчиками; перечислить фактически используемых обработчиков в политике.
7. Провести юридическую проверку документов под реальные бизнес-процессы. Публичные
   тексты не заменяют уведомление Роскомнадзора, внутренние локальные акты, модель
   угроз, назначение ответственного и организационно-технические меры защиты.

Актуальность шаблона: 18 сентября 2026 года.
